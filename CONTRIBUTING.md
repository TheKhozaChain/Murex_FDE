# Contributing

Thank you for helping improve the Murex FDE Workbench. Keep all data, identifiers, workflows, logs, and documentation fictional. Do not contribute proprietary schemas, screenshots, field names, configuration, client information, or copyrighted vendor material.

Before a pull request, run `npm test` and `npm run lint`. Add or update tests for domain and guardrail changes. Explain any modification to deterministic/AI/human decision boundaries and update the threat model when a new action, provider, or data source is introduced.

Use Conventional Commits where practical. Version releases with semantic versioning: patch for fixes and synthetic content, minor for backward-compatible capabilities, and major for incompatible domain or workflow changes.
